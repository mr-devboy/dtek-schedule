# ⚡️ DTEK Schedule

Автоматичне отримання графіку планових відключень електроенергії від ДТЕК зі сповіщеннями в Telegram.

## 💖 Підтримка

Якщо проєкт корисний для тебе, не забудь поставити ⭐️ та [підтримати донатом](https://send.monobank.ua/jar/3QTpZrNn2T).

## 📋 Опис

Проєкт автоматично отримує графік планових відключень електроенергії на сайті ДТЕК для вказаної групи та відправляє сповіщення в Telegram з детальним розкладом на поточний день. Перевірка розкладу запускається щогодини через GitHub Actions.

## ✨ Можливості

- 🤖 Автоматичне отримання графіку відключень електроенергії щогодини.
- 📱 Надсилання сповіщень в Telegram з детальним розкладом на день.
- ♻️ Оновлення існуючого повідомлення, якщо графік не змінився.
- ↩️ Надсилання нового повідомлення у відповідь на попереднє, якщо графік змінився.
- 📊 Відображення часових проміжків з електроенергією та без неї.
- 🌙 Тихі сповіщення в нічний час (00:00-08:00).
- 🔄 Автоматичний запуск через GitHub Actions.
- 🗂 Зберігання стану бота в окремій гілці `artifacts`, щоб у `main` був лише код.

## 🚀 Швидкий старт

### 1. Форк репозиторію

Натисни кнопку "Fork" у правому верхньому куті сторінки репозиторію.

### 2. Створення Telegram бота

1. Відкрий [@BotFather](https://t.me/BotFather) в Telegram.
2. Відправ команду `/newbot`.
3. Вкажи ім'я та username для бота.
4. Збережи отриманий токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### 3. Отримання Chat ID

1. Відправ будь-яке повідомлення своєму боту.
2. Відкрий у браузері `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`.
3. Знайди значення у форматі `"chat":{"id":123456789}` — це твій Chat ID.

### 4. Визначення твоєї групи відключень

1. Перейди на сайт ДТЕК свого регіону, наприклад [КРЕМ](https://www.dtek-krem.com.ua/ua/shutdowns).
2. Введи свою адресу (місто, вулиця, будинок).
3. Знайди та збережи в результатах номер своєї групи (наприклад `1.2`).

### 5. Налаштування Secrets

Перейди в **Settings** → **Secrets and variables** → **Actions** свого форкнутого репозиторію та додай наступні secrets:

| Secret               | Опис                                    | Приклад                                                                                          |
| -------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather                | `123456789:ABCdefGHI...`                                                                         |
| `TELEGRAM_CHAT_ID`   | ID чату в Telegram                      | `123456789` або `-123456789` (для каналу)                                                        |
| `REGION`             | Регіон ДТЕК                             | `k` — Київ, `kr` — Київська обл., `dn` — Дніпровська обл.,`o` — Одеська обл.,`d` — Донецька обл. |
| `GROUP`              | Номер групи відключень без префіксу GPV | `1.2`                                                                                            |

### 6. Запуск Actions

1. Перейди на вкладку **Actions**.
2. Знайди та відкрий workflow з назвою **"Run power outages schedule generator"**.
3. Праворуч вгорі натисни **Run workflow** → і ще раз на **Run workflow** всередині випадного меню.

## 🛠 Локальний запуск

### Вимоги

- Node.js (версія вказана в `.nvmrc`)
- npm

### Встановлення

```bash
# Клонування репозиторію
git clone https://github.com/YOUR_USERNAME/dtek-schedule.git
cd dtek-schedule

# Встановлення залежностей
npm install

# Встановлення Playwright залежностей
npx playwright install chromium
```

### Налаштування

Створи файл `.env` в кореневій директорії з наступним вмістом:

```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-12346789
REGION=kr
GROUP=1.2
```

### Запуск

```bash
# Для разового запуску
npm run start

# Для автоматичного перезапуску
npm run watch
```

## 🔍 Як це працює

1. **Отримання даних**: Скрипт використовує Playwright для відкриття сайту ДТЕК та парсингу даних про графік відключень.
2. **Генерація розкладу**: На основі отриманих даних формується детальний розклад з годинними та напівгодинними інтервалами. Якщо графіка на сьогодні немає, повідомлення не надсилається.
3. **Формування повідомлення**: Створюється структуроване повідомлення з переліком часових проміжків відключень.
4. **Відправлення в Telegram**: Повідомлення відправляється боту, з тихим режимом у нічний час (00:00-08:00).
5. **Оновлення повідомлення**: Поки графік не змінюється, оновлюється раніше відправлене повідомлення. Якщо графік змінився, надсилається нове повідомлення у відповідь на попереднє, щоб було видно різницю. Перше повідомлення нового дня надсилається окремо.
6. **Збереження стану**: Інформація про останнє повідомлення зберігається у файлі `last-message.json` в окремій гілці `artifacts`. Workflow підключає цю гілку як папку `artifacts/` і після роботи скрипта комітить зміни назад. У новому форку гілка створюється автоматично під час першого запуску. При локальному запуску стан зберігається в папці `artifacts/`, яка не потрапляє до репозиторію.
7. **Захист від вимкнення**: GitHub автоматично вимикає заплановані workflow у публічних репозиторіях після 60 днів без активності, тому наприкінці кожного запуску workflow вмикає сам себе через GitHub API.

## ⚙️ Налаштування

### Зміна частоти перевірки

Відредагуй cron вираз у файлі `.github/workflows/schedule.yml`:

```yaml
schedule:
  - cron: "0 * * * *" # щогодини
```

Приклади:

- `*/30 * * * *` - кожні 30 хвилин
- `0 */3 * * *` - кожні 3 години
- `0 6,12,18 * * *` - тричі на день (6:00, 12:00, 18:00)

## 📝 Формат груп

Проєкт підтримує групи у форматі **GPVX.X**, де:

- X.X - номер твоєї групи (наприклад, 1.1, 2.3, 5.1)
- В налаштуваннях вказується лише число без префіксу GPV

Приклади валідних груп:

- `1.1` → GPV1.1
- `2.3` → GPV2.3
- `5.1` → GPV5.1

## 🕐 Стани електропостачання

Проєкт розпізнає чотири типи станів:

- **Електроенергія є** - повна година з електроенергією.
- **Електроенергії немає** - повна година без електроенергії.
- **Перша половина без світла** - 00-30 хвилин без світла, 30-60 хвилин зі світлом.
- **Друга половина без світла** - 00-30 хвилин зі світлом, 30-60 хвилин без світла.

## ⚠️ Обмеження

Графік не зможе працювати у разі недоступності сторінки `/shutdowns` або зміни структури даних на ній.

## 🔧 Повторні спроби

Проєкт автоматично намагається виконати операцію повторно у випадку помилки:

- Максимум 5 повторних спроб для отримання даних та відправлення повідомлень.
- Затримка між спробами: 5 секунд.
- Якщо всі спроби невдалі, запуск у GitHub Actions завершується з помилкою.
